# 主線任務系統 PRD (產品需求文件)

## 1. 專案概述

### 背景與動機
「冒險者金庫」是一款創新的遊戲化個人財務管理系統。為了讓新註冊的冒險者能熟悉系統的核心功能，系統提供「主線任務」，透過劇情引導的方式，讓使用者在遊戲化情境中完成「開戶」與「保單分析」，熟悉金庫操作的同時獲得虛擬獎勵，增加使用者的黏著度。

### 核心價值主張
- **故事化引導**：將繁瑣的開戶與金融分析程序轉化為史詩級的冒險任務。
- **即時回饋**：完成任務即時分發經驗值（EXP）與金幣（Gold），並有升級特效，提供強大的成就感。
- **流暢體驗**：純前端 Fetch API 異步串接，無重載頁面，配合精美奇幻的視覺特效。

## 2. 功能需求

### 功能 1：冒險者角色面板 (Adventurer Status Panel)
- 顯示當前冒險者的基本資訊：等級 (Level)、經驗值 (EXP)、金幣 (Gold)。
- 經驗值條使用動態百分比顯示，並且在等級提升時會以動畫方式重置並增加等級。

### 功能 2：劇情式「開戶任務（契約之印）」(Account Opening Quest)
- **劇情設定**：冒險者必須與金庫公會簽訂「契約之印」，才能啟用金庫保險箱存取財富。
- **表單欄位**：
  - 冒險者真名 (`real_name`) - 必填，長度至少 2 字。
  - 冒險職業 (`character_class`) - 下拉選單（戰士/法師/盜賊/牧師）。
  - 金庫安全密碼 (`vault_password`) - 必填，至少 6 字。
  - 冒險執照編號 (`license_number`) - 必填，格式為 `ADV-` 開頭接 5 碼數字。
- **提交處理**：
  - 前端驗證格式正確後，發送 Fetch POST 請求。
  - 後端驗證欄位合法性，建立開戶記錄，將任務狀態改為已完成，派發獎勵：**+100 金幣, +150 經驗值**。

### 功能 3：劇情式「保單分析任務（命運之御）」(Insurance Analysis Quest)
- **前置條件**：必須完成「開戶任務」後才能解鎖！未解鎖時顯示鎖定狀態。
- **劇情設定**：冒險者進入高風險地下城前，需進行「命運之御」防護評估，分析人身與財產保險的覆蓋程度。
- **表單欄位**：
  - 冒險風險等級 (`risk_level`) - 單選按鈕（高風險/中風險/低風險）。
  - 期望保額 (`coverage_amount`) - 數字輸入，必填，範圍 10,000 ~ 1,000,000 金幣。
  - 主要投保類型 (`insurance_type`) - 多選核取方塊（人身意外險、裝備損毀險、財寶盜竊險）。
- **提交處理**：
  - 前端 Fetch POST 提交後，後端進行保額與風險級別的逻辑檢驗，更新資料庫，將任務狀態改為已完成，派發獎勵：**+250 金幣, +300 經驗值**。

## 3. 非功能需求

### 技術限制
- **前端**：純 HTML / CSS / JavaScript (ES6 Fetch)。
- **後端**：Python Flask (不使用大型 ORM，使用原生 `sqlite3` 提供清晰的資料庫流程)。
- **資料庫**：SQLite (`instance/database.db`)。

### 效能與安全性
- 後端路由與 API 均需實作 `try...except` 異常處理與參數防錯驗證。
- SQLite 資料庫連線需自動關閉，避免併發鎖死或記憶體洩漏。

## 4. MVP 範圍 (Minimum Viable Product)

| 功能層級 | 功能名稱 | 說明 |
| :--- | :--- | :--- |
| **Must Have** | 冒險者狀態 API & 顯示 | 顯示等級、金幣、經驗值並持久化於 SQLite |
| **Must Have** | 開戶任務表單與提交 | 前後端串接、資料格式驗證與獎勵發放 |
| **Should Have** | 保單分析任務解鎖與表單 | 偵測開戶任務狀態，動態解鎖，提交後發放更高獎勵 |
| **Should Have** | 精美奇幻 CSS 玻璃擬態 | 打造視覺驚艷的奇幻冒險風格 UI |
| **Nice to Have** | 金色粒子灑落動畫與升級特效 | 完成任務及升級時提供炫麗的 Canvas 粒子特效 |
